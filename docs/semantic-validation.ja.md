# 動作の回帰検証

バイトコード検証は JVM 上の構造を調べるもので、動作の等価性を証明するものではありません。core の差分テストは、元と変換後を別のクラスローダーで実行し、同じ操作ごとの戻り値・例外型とメッセージ・内部状態・副作用を比較します。明示した期待状態も併用し、両方が同じ誤りを持つケースを検出します。変換後のローダーに元のアプリケーションクラスは渡しません。

JDK 21 で実行します。スクリプトはテスト JVM に `-Xverify:all` を追加し、`--full` では core と CLI の全テストを実行します。

```sh
python3 scripts/verify-semantic-regressions.py
python3 scripts/verify-semantic-regressions.py --full
```

`StatefulDifferentialTest` は整数演算、light 制御フロー、呼び出し間接化／prelink 生成、文字列、数値、リネームを個別に検証し、その併用も検証します。各構成は seed 0、1、20261022、`Long.MIN_VALUE` を使います。併用構成は strong と明示的 light、定数フィールド変換、パッケージ平坦化、ジェネリックシグネチャ削除、メソッドあたり演算変換 4 件、VM 選択なしです。予算は入力命令 10000、分岐 256、追加命令 1024、成長率 300%、出力コード 60000 バイトです。これは利用側の設定値を使う汎用 fixture であり、Bukkit やゲーム仕様には依存せず generic platform で実行します。

初期化→開始→進捗なし→負数入力→終了境界の直前→境界一致→終了後の操作拒否を検証します。開始操作だけでは終了せず、整数オーバーフローも JVM のラップに従うことを期待状態で確認します。評価順序、int/long、負数、シフト距離のマスク、ゼロ除算、catch/rethrow、finally の副作用も比較します。併用時を含め、指定した変換が実際に適用されたことも確認します。

`KotlinStatefulDifferentialTest` は Kotlin の interface 呼び出しと default 引数、value class 引数を持つ private default、data class の copy／分解、enum 名、lazy 委譲、キャプチャ付きラムダ、callable reference を併用構成で検証します。明示的 keep は観測用の 2 メソッドだけで、他は通常のコンパイラ契約保護に従います。

## 初期化順序の回帰

`InitializationSemanticsTest` は、有効なバイトコードでも意味が変わる次の問題を再現します。

- 親クラスの初期化から子のメソッドを呼び、子の `ConstantValue` を `GETSTATIC` で読む。JVM では定数の設定が上位型の初期化より先ですが、子の `<clinit>` に移すと 7 が 0 になりました。
- 同じ再入経路で子の文字列メソッドを呼ぶ。文字列キャッシュがまだ設定されておらず、従来は `NullPointerException` になりました。通常長と大型暗号化ペイロードの両方を確認します。

定数抽出は `Object` 以外の親クラス、または実装・継承インターフェースを持つクラスで属性を保持します。外部上位型や default メソッドのない interface も含む保守的な判定です。上位型全体の初期化動作を証明する処理は実装していません。レポートに `initializationSkippedClasses` を集計し、既存の初期化メソッドには `constant-preparation-before-supertype-initialization` を記録します。通常メソッドのリテラル変換は続けます。外部 API 定数の明示的 keep も従来どおり必要です。

文字列アクセサーは、キャッシュ未設定時には復号して intern した値を直接返し、設定後は既存の atomic cache を使用します。大型文字列も同じ扱いです。null 判定が追加されますが、実行性能はこれらのテストでは測定していません。

## 残る境界

| 項目 | 確認範囲と制限 |
| --- | --- |
| 整数 | 代数変換は int/long の加減算と XOR のみ。評価順を保持します。浮動小数点演算・シフト・除算は代数変換せず、数値・分岐変換との相互作用を境界入力で確認します。 |
| 制御フロー | light は直接分岐と例外ハンドラーの優先順を保持します。既存テストでは入れ子の例外・finally・monitor も検証します。全 CFG やスケジュールを網羅しません。 |
| 間接呼び出し | コンストラクター・クラス初期化・synthetic・未対応呼び出し形式を除外します。既存 prelink テストで範囲制限と対象初期化も確認します。完全なスタックトレース・時間・リンク失敗の等価性は検証しません。 |
| 文字列・定数 | intern による同一性と初期化再入を確認します。抽出対象の外部 API 定数は Java のコンパイル時定数でなくなるため keep が必要です。OOM・全並行実行順・初期化デッドロックは対象外です。 |
| Kotlin/JVM 契約 | メタデータとコンパイラ ABI の保護に加え、既存 relocation テストでは利用側の再コンパイル・reflection を確認します。動的に構築する reflection 名、シリアライズ名、外部設定、未知の compiler/plugin metadata は keep または拒否が必要です。 |

## 成果物の由来と実製品の検証

入力・出力・mapping・レポートの SHA-256、ツール、設定、解決済み依存クラスパスを記録します。同じバージョンや時刻だけで同一入力と判断しません。再現可能なら同じツール・入力・設定・依存で別の出力先へ再生成し、JAR と 3 レポートをバイト単位で比較します。エンジン修正後は再生成が必要で、古い JAR は修正版の検証になりません。実行ごとのハッシュとログはコミット対象外に保存します。

確認できるのは、実行した JVM と入力・操作列の範囲です。実 Paper の試合・scheduler・ネットワーク・実プレイヤーは動かしておらず、全製品経路・並行性・全 JVM/OS・完全な等価性は保証しません。MockBukkit で CraftPlayer が存在しない停止は環境上の制限であり、変換不具合の証拠として扱いません。
