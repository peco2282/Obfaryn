# 無料版と追加保護の開発方針

[English](edition-policy.md)

公開済みの機能を無料版の基準とし、不具合修正・互換性対応・通常の改善を継続する。この方針は有料版の発売、ライセンス変更、保護効果の保証を意味しない。

## 変更の配置

| 対象 | 配置先 |
| --- | --- |
| 公開API、拡張契約、CLI、Gradle連携、既存プラットフォーム対応 | 無料版 |
| 既存のリネーム、定数保護、呼出し間接化、制御フロー、明示選択型VM | 修正・通常の改善を含め無料版 |
| 検証、構造予算、ロールバック、基本レポート、配布物監査 | 無料版 |
| 新規の条件比較間接化とCode Capsule | 評価待ちの追加保護・有料候補 |
| 復元評価、アプリ固有のプローブ、採用を見送った試作 | 実験 |

有料候補とする条件は、追加価値・互換性上の制約・実行コストを説明し検証できること。新しいコミットや複雑な符号化だけを課金理由にしない。有料候補の開発中に見つかった安全性・正確性の修正も無料版へ反映する。

## ブランチ運用

- `main` と `codex/community`：公開済みの基準から整理した無料版の変更。
- `codex/additional-protection`：無料版を土台とする追加保護・有料候補。無料版の修正を取り込む。このブランチ全体を `main` にマージしない。
- `codex/protection-experiments`：追加保護ブランチを土台とする復元・評価ツールと記録。再利用可能なツールは個別にレビューして取り込む。
- `codex/pre-commercial-split`：分離前の全履歴を保持する参照用ブランチ。統合には使わない。

追加保護・実験ブランチはローカルの整理用ブランチとする。公開先を決める前に内容とライセンスを確認する。ブランチ分離だけでは別配布・別ライセンスの製品にはならない。評価によって製品化の根拠を得た場合、次の段階で公開assembly契約を使う拡張として分離する。そのパッケージ分離は今回の履歴整理には含まれない。

既存のMPL対象コードと出力・ランタイム例外の条件は維持する。ブランチやファイルの移動だけではライセンスは変わらない。評価記録は検証範囲を明示し、一般的な解析耐性や性能の保証として扱わない。
